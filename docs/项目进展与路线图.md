## 一、项目概览

一句话：**以番茄钟为入口，把「今天专注了什么、心情如何、想了什么」沉淀成一条可回看的日历时间线。**

- 本地优先：数据只在本机（SQLite），不联网、无账号
- 桌面端：托盘常驻、全局快捷键、系统通知、关闭到托盘
- 数据可迁移：JSON 全量导出/导入，单篇日记可导出 Markdown

## 三、当前限制（如实记录）

**功能层面**

- 没有云同步 / 多设备（设计上 v1 明确不做）
- 统计页「更完整报表」仍是占位：无心情-专注相关性、无标签分布、无周报/年报
- 日历只有月视图，没有周视图、年视图（年热力图）
- 日记不支持插图、表格、富文本
- 名言是内置静态数据，不能自定义或导入
- 快捷键只有两个，不能自定义
- 无自动更新机制
- 单语言（中文），未做 i18n

**数据层面**

- 跨时区旅行时历史记录可能按新时区显示（`local_date` 是写入时快照，仅影响展示）
- 迁移只在"空库→v2"和"单次升级"路径验证，未做多版本连续升级回归
- 删除是物理删除 + 6 秒撤销，没有回收站

**工程质量**

- 无单元测试、无 E2E；验证靠类型检查 + 浏览器 CDP 冒烟
- 前端主包约 520 KB（gzip 176 KB），未做代码分割
- Rust 侧目前只做插件注册与窗口/托盘，计时逻辑仍在前端（`useRemaining`）
- 安装包未签名，首次运行会被 SmartScreen 拦截

pnpm dev                 # http://localhost:5183

pnpm tauri:dev

**已知环境坑**

| 现象 | 处理 |
| --- | --- |
| `D8050 无法执行 c1.dll` | 已在 `Cargo.toml` 设 `[profile.dev] debug = 0` |
| release 白屏且地址是 `localhost:5183` | 必须 `pnpm tauri build`，不能直接 `cargo build --release` |
| `os error 5` | WebView2/DB 目录不可写，程序会回退到 exe 同级 `data\` |
| git push 被 reset | `git -c http.https://github.com.proxy=http://127.0.0.1:7897 push` |

## 七、协作方式（供后续参考）

本项目采用「文档先行 + 文件所有权 + 多 agent 并行」：

1. 先写改进文档，定义**数据契约与组件契约**
2. 每个 agent 只改自己独占的文件，禁止跨目录
3. 主线程负责接线（App.tsx、页面集成）、`tsc`/`build` 验证、截图核对
4. 出现接口不一致时，以文档为准修改代码，而不是临时改契约

这套流程在 v2（3 agents）和 v3（3 agents）中验证过，未出现文件覆盖冲突。
